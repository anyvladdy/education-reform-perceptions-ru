# Этап 2 без ключей: сайты министерств и публичные каналы Telegram

> **Статус: задел на будущее.** По [методологии](../METHODOLOGY.md) 2.2 (решение от 15.10.2026) досбор не проводится. Сборщики работают и проверены пилотом, но их результаты не входят в анализируемый корпус без нового решения команды.

Вариант сбора без API, ключей и входа в аккаунты: только `requests` и Selenium. Версия с API (чаты Telegram, ВКонтакте) лежит в [`../stage2/`](../stage2/README.md). Обе пишут таблицы в одной схеме (методология 4.3), поэтому их результаты можно объединить.

| Источник | Как собирается | Чего нет |
| :-- | :-- | :-- |
| Сайты министерств: edu.gov.ru, minobrnauki.gov.ru, веб-архив | `requests` + BeautifulSoup. Код общий со `stage2/src/ministry_sites.py` | — |
| Публичные каналы Telegram: 2 министерства, 5 вузов, 3 колледжа | Лента `t.me/s/<канал>` через `requests` | Реакций (исключены методологией) |
| Комментарии под постами этих каналов | Selenium открывает виджет обсуждения `t.me/<канал>/<пост>?embed=1&discussion=1` и догружает все комментарии | Ролей администраторов: без входа их не видно (см. ниже) |

**Что в этот вариант не входит:**
- **Чаты Telegram** (ИТМО, ДВФУ): без входа они не видны вовсе.
- **ВКонтакте**: без входа сообщества не показываются.

Поэтому у двух колледжей основного набора — Колледжа туризма в Санкт-Петербурге и Химико-технологического колледжа в Новосибирске — нет данных: у них только VK. Им нужна замена с публичным Telegram-каналом. У МГПУ и УрФУ взяты общие каналы вузов из резерва реестра, а не каналы приёмных комиссий: сообщества приёмных комиссий этих вузов есть только во VK.

## Установка и запуск

```bash
cd stage2_selenium
python3 -m venv .venv          # если папки .venv ещё нет
.venv/bin/pip install -r requirements.txt
.venv/bin/python check_parsers.py                  # офлайн-проверка
.venv/bin/python collect.py --source all --mode pilot
.venv/bin/python collect.py --source all --mode full
.venv/bin/python collect.py --source telegram --only uni_dvfu_tg --mode full
```

- **Браузер.** Нужен установленный Google Chrome. Драйвер Selenium скачает сам.
- **Ключи** не нужны. Соль для псевдонимов авторов создаётся автоматически при первом запуске в `.secrets/hash_salt`. Не удаляйте этот файл: иначе псевдонимы нового запуска не совпадут со старыми.
- **Режимы** `pilot` и `full`, окна (`config.json`, 1 июня – 30 сентября каждого года) и возобновление после остановки работают так же, как в `stage2/`.
- **Скорость.** Полный сбор комментариев медленный: каждый пост — отдельная страница в браузере.

## Результаты (`data/<mode>/`)

- `official_sites.csv` и `telegram_web.csv` — одна строка на пост или комментарий.
- `collection_log.csv` — журнал ошибок, недоступностей и пропусков; `manifest_<run_id>.json` — параметры запуска и SHA-256 таблиц.
- **Комментарии:**
  - у каждого есть `record_id` с префиксом `c`;
  - `thread_id` — номер поста;
  - `parent_id` — пост или комментарий, на который дан ответ. Цитата родительского сообщения в `text_raw` не входит.
- **Автор комментария** сохраняется только как `sender_hash` (псевдоним) и `sender_kind`. Имена и логины не записываются.

## Ответы приёмной комиссии

Если комиссия отвечает от имени канала, комментарий получает `sender_kind = organization` автоматически. Если отвечает сотрудник с личного аккаунта, без входа это не определить: в пилоте ДВФУ ни один комментарий не пришёл от имени канала. Поэтому роли проверяются вручную:

1. `python authors.py summary` создаёт `data/<mode>/authors_summary.csv` — самых активных авторов каждого канала. Для каждого указаны число комментариев, сколько раз он отвечал другим, в скольких ветках участвовал и ссылка на пример комментария.
2. Откройте ссылку в браузере. По профилю и ответам решите, сотрудник ли это: подпись, упоминание приёмной комиссии, ответы от лица вуза. Решение записывается до содержательного анализа (методология, раздел 4.6).
3. Подтверждённые псевдонимы впишите в `config.json`, в поле `"staff_verified": {"uni_dvfu_tg": ["…"]}`.
4. `python authors.py apply` создаёт `telegram_web_roles.csv`: у подтверждённых авторов будет `sender_kind = staff_verified`. Исходная таблица не меняется.

## Ограничения

- **Комментарии доступны не везде.** У части постов обсуждение закрыто («Discussion is not available»); число таких постов пишется в журнал.
- **Ранние посты могли исчезнуть.** Лента `t.me/s/` показывает только сохранившиеся посты, удалённые не восстанавливаются. Глубина истории разная: например, канал абитуриентов ДВФУ начинается в июне 2023 года.
- **Тексты не обезличены.** В `text_raw` комментариев могут быть имена и контакты. Перед разметкой нужна обезличенная версия (методология, раздел 8).
